# 📚 Understanding the API Relationships - CECAB CMS

Let me explain each endpoint and their relationships clearly:

---

## 1. PAGES (`/api/orgs/pages/`)

### What it is:
Pages are the **static/semi-static content pages** of your website (e.g., Home, About Us, Contact).

### Structure:
```
Page
├── id
├── title (translatable)
├── slug (URL identifier)
├── active (boolean)
├── order (menu position)
└── blocks (PageContentBlock[])
    ├── block_type (hero | text | process)
    ├── title (translatable)
    ├── content (HTML, translatable)
    ├── image (optional)
    └── order (within page)
```

### Relationships:
- **Page → PageContentBlock**: One-to-Many (a page has multiple blocks)
- **No direct relationship** to Catalog or Blog

### Use Case:
```
Home Page → Blocks: Hero, About Text, Featured Products
About Page → Blocks: History Text, Team Photos
Contact Page → Blocks: Contact Form, Map
```

### API Example:
```json
GET /api/orgs/pages/fabrica-de-chocolate/
{
  "id": 3,
  "title": "Fábrica de Chocolate",
  "slug": "fabrica-de-chocolate",
  "active": true,
  "order": 2,
  "blocks": [
    {
      "id": 5,
      "block_type": "hero",
      "title": "Bem-vindo à Fábrica",
      "content": "<p>Descubra como fazemos chocolate...</p>",
      "image": "/media/orgs_api/cms/pages/blocks/hero.jpg",
      "order": 0
    },
    {
      "id": 6,
      "block_type": "process",
      "title": "Da Amêndoa à Barra",
      "content": "<p>Etapa 1: Colheita...</p>",
      "image": null,
      "order": 1
    }
  ]
}
```

## 2. CATALOG-CATEGORIES (`/api/orgs/catalog-categories/`)

### What it is:
**Product/Service categories** that organize your catalog items (chocolates, accommodations, tours, etc.).

### Structure:
```
Category
├── id
├── name (translatable)
├── slug (URL identifier)
└── items (CatalogItem[]) - NESTED! (from CategoryDetailSerializer)
    ├── id
    ├── name (translatable)
    ├── slug
    ├── description (translatable)
    ├── price
    ├── is_available
    ├── picture
    ├── average_rating
    ├── total_reviews
    └── specifications[]
```

### Relationships:
- **Category → CatalogItem**: One-to-Many (a category has many items)
- **CatalogItem → Category**: Many-to-One (each item belongs to one category)
- **CatalogItem → Specifications**: One-to-Many
- **CatalogItem → Reviews**: One-to-Many

### Use Case:
```
Chocolates Category
├── Chocolate Amargo 70%
├── Chocolate ao Leite
└── Chocolate Branco

Alojamento Category
├── Suite Familiar
└── Quarto Standard
```

### API Example:
```json
GET /api/orgs/catalog-categories/
[
  {
    "id": 1,
    "name": "Chocolates",
    "slug": "chocolates",
    "items": [
      {
        "id": 1,
        "name": "Chocolate Amargo 70%",
        "slug": "chocolate-amargo-70-0",
        "price": "12.50",
        "is_available": true,
        "average_rating": "4.80",
        "total_reviews": 25
      }
    ]
  }
]
```

## 3. CATALOG-ITEMS (`/api/orgs/catalog-items/`)

### What it is:
**Individual products, accommodations, tours, or services** that you sell or offer.

### Structure:
```
CatalogItem
├── id
├── category (FK to Category)
├── category_name (read-only, from serializer)
├── name (translatable)
├── slug
├── description (translatable)
├── price
├── is_available
├── picture
├── average_rating (cached)
├── total_reviews (cached)
└── specifications[]
    ├── key (translatable)
    └── value (translatable)
```

### Relationships:
- **CatalogItem → Category**: Many-to-One
- **CatalogItem → Specifications**: One-to-Many
- **CatalogItem → Reviews**: One-to-Many
- **Reviews → User**: Many-to-One (authenticated users)

### Use Case:
```
Each product/service is a CatalogItem:
- "Chocolate Amargo 70%" (product)
- "Suite Familiar" (accommodation)
- "Tour da Plantação" (service)
- "Oficina de Chocolate" (workshop)
```

### API Example:
```json
GET /api/orgs/catalog-items/?category__slug=chocolates
[
  {
    "id": 1,
    "category": 1,
    "category_name": "Chocolates",
    "name": "Chocolate Amargo 70%",
    "slug": "chocolate-amargo-70-0",
    "description": "Chocolate premium com 70% de cacau...",
    "price": "12.50",
    "is_available": true,
    "picture": "/media/orgs_api/cms/catalog/chocolate.jpg",
    "specifications": [
      {
        "id": 1,
        "key": "Origem",
        "value": "São Tomé e Príncipe"
      }
    ]
  }
]
```

## 4. CATEGORIES (`/api/orgs/categories/`) - BLOG CATEGORIES

### What it is:
**Blog/News categories** that organize your editorial content.

### Structure:
```
BlogCategory
├── id
├── name (translatable)
├── slug (URL identifier)
└── posts[] (from nested router)
    ├── id
    ├── title (translatable)
    ├── slug
    ├── picture
    ├── description (translatable)
    ├── text (translatable)
    ├── date
    ├── active
    ├── featured
    └── ...more fields
```

### Relationships:
- **BlogCategory → Post**: One-to-Many (a category has many posts)
- **Post → BlogCategory**: Many-to-One (each post belongs to one category)
- **Post → Information**: One-to-Many (FAQ entries)
- **Post → PostImage**: One-to-Many (gallery)
- **Post → PostVideo**: One-to-Many (videos)
- **Post → PostDocument**: One-to-Many (downloadable files)

### Use Case:
```
Notícias Category
├── CECAB celebra 10 anos
├── Nova rota turística
└── Projeto de sustentabilidade

Eventos Category
├── Festival de Chocolate
└── Oficina de Chocolate
```

### API Example:
```json
GET /api/orgs/categories/noticias/posts/
[
  {
    "id": 1,
    "title": "CECAB celebra 10 anos de produção",
    "slug": "cecab-celebra-10-anos",
    "category_slug": "noticias",
    "picture": "/media/orgs_api/cms/posts/images/post.jpg",
    "active": true,
    "date": "2024-01-15T10:00:00Z",
    "featured": true,
    "description": "Resumo da notícia..."
  }
]
```

## 📋 SUMMARY TABLE

| Endpoint | Purpose | Relationship | Has Children? | Belongs To |
|----------|---------|--------------|---------------|------------|
| **Pages** | Static content pages | Page → PageContentBlock | Yes (Blocks) | - |
| **Catalog-Categories** | Product/Service categories | Category → CatalogItem | Yes (Items) | - |
| **Catalog-Items** | Individual products/services | Item → Specifications, Reviews | Yes (Specs, Reviews) | Category |
| **Categories** (Blog) | Blog post categories | BlogCategory → Post | Yes (Posts) | - |

---

## 🔑 KEY DIFFERENCES

### Catalog-Categories vs Categories (Blog)

| Feature | Catalog-Categories | Categories (Blog) |
|---------|-------------------|-------------------|
| **Purpose** | Organize products/services | Organize blog posts/news |
| **Children** | CatalogItems (products) | Posts (articles) |
| **URL** | `/catalog-categories/` | `/categories/` |
| **Nested API** | Items included in response | Posts via nested router: `/categories/{slug}/posts/` |

### Pages vs Everything Else

| Feature | Pages | Catalog/Blog |
|---------|-------|--------------|
| **Content Type** | Static/Semi-static | Dynamic |
| **Structure** | Blocks (hero, text, process) | List of items/posts |
| **Updates** | Infrequent | Frequent |
| **User Interaction** | Read-only | Reviews, Comments |

## 🛠️ ADMIN MANAGEMENT TIPS

### Managing Pages:
1. Create a **Page** (e.g., "Fábrica de Chocolate")
2. Add **PageContentBlocks** to it
3. Order blocks with the `order` field
4. Each block can be a hero banner, text section, or process steps

### Managing Catalog:
1. Create a **Category** (e.g., "Chocolates")
2. Create **CatalogItems** (e.g., "Chocolate Amargo 70%")
3. Add **Specifications** to each item
4. Reviews are automatically added by users through the frontend
5. Ratings are auto-calculated

### Managing Blog:
1. Create a **BlogCategory** (e.g., "Notícias")
2. Create **Posts** under that category
3. Add images, documents, videos
4. Add FAQ entries for service posts
5. Mark posts as featured or to front page

## 📊 API FLOW EXAMPLES

### Frontend Navigation Flow:
```
1. User visits Home Page
   → GET /pages/inicio/
   → Renders blocks

2. User clicks "Catálogo"
   → GET /catalog-categories/
   → Shows category list with items

3. User clicks "Chocolates"
   → GET /catalog-categories/chocolates/
   → Shows all chocolate products

4. User clicks a product
   → GET /catalog-items/chocolate-amargo-70-0/
   → Shows product details with reviews

5. User leaves review
   → POST /reviews/
   → Updates product rating

6. User clicks "Blog"
   → GET /categories/noticias/posts/
   → Shows news posts

7. User clicks an article
   → GET /categories/noticias/posts/cecab-celebra-10-anos/
   → Shows full article content
```

This should give you a clear understanding of all relationships and how to manage content across the system! 🚀
